AWANA Roster & Reports: user manual

This app replaces the Google Sheets and Excel workbooks. It runs entirely in your browser: there is no server of its own, your file goes only where you save it (this computer, or your Google Drive if you turn that on), and it works from a file on your computer as well as from the website. Everything you record lives in one data file that you open at the start of a session and download when you are done.

1. Quick start

  1. Open your data file. On the opening screen (or Import… in the top bar) choose the newest awana-2026-27-….json. It holds the whole roster, color teams, calendar, rotation and everything recorded so far, so nothing else is needed.
  2. Work. Use the tabs: take attendance, enter game results, record awards and progress, print reports.
  3. Download data file (blue button, top right) when you are done. That saves a new file whose name ends in the date and time (for example awana-2026-27-20261104-203015.json). Keep it: it is next week’s starting point.

Apply changes and Discard. On the Roster, Person, Color teams, Uniforms and Calendar tabs (and on Attendance if you tick Hold changes until I apply them), a change is held as a draft: you see it at once, but it is not in History and cannot be undone until you press Apply changes in the bar under the tabs. Open What changed there to check the list, make corrections, then Apply; Discard puts the tab back as it was. Apply writes one History line named for the tab. Leaving the tab, or pressing Download data file, asks you to apply first. Undo and Redo wait while a draft is open. Attendance, Games, Awards and Progress are live: each tick is kept as you tap it (a phone always works this way). An Undo or Redo is its own History line, labeled Undo: or Redo:, so the log stays a complete record. Apply changes keeps your edits in the program; Download data file is what writes the file.

The top bar always shows whether you have unsaved changes, how many edits there are, and when the last download started. Edits you made here to a Planning Center field are counted in the bar under the tabs (1 change is needed in Planning Center, with a link to the list): under the Apply line on a tab with held changes, alone on any other tab, and it goes away once an import matches them. The line turns bold after 20 edits or 15 minutes without a download. It says download started, not saved: a browser cannot tell whether you cancelled the save box, so check that the file is in your Downloads folder. If you try to close or reload the page with unsaved changes, the browser asks first.

2. The files, saving and Google Drive

The data file (the one that matters)

  • A single JSON file named awana-<year>-<yyyymmdd-hhmmss>.json. The tag at the end is the date and time it was downloaded, so every save is a new file and the older ones are automatic backups. Always open the one with the newest tag.
  • It holds: the roster with the full Planning Center record as of the last import (including medical, allergy, emergency contact, phone, email and address), color teams and any mid-quarter team moves, vest and shirt tracking, notes, pending Planning Center changes, the calendar, the nightly rotation, attendance (with one-night teams), games, awards, the Adult Memorization list for the slides, handbooks (book, date received and note), progress, award lists, book codes and slide wording, and the change history. The settings on the Reports tab and Options (club title, save and update choices) are kept in the file, so they follow it. The file is written compactly (no indentation, and each person’s Planning Center record as a list of values), and it never stores anything the app can work out, such as game points, pace or standings, so it stays small. A file from an older version opens and is upgraded when you next download; a file from a newer version is refused by an older app, so update the page first (see Update now below).
  • Because it holds children’s details, treat it like the Planning Center export itself: do not email it or put it on a shared drive that others can open.

The Planning Center export (optional, only to merge updates)

  • A CSV exported from Planning Center, named like 20261028 -- demo-club-2026-27.csv. The leading yyyymmdd becomes the “Planning Center data as of” date shown on reports; without it, the date you opened the file is used.
  • You do not need it to work, print or run reports: the data file already holds the roster as of its last import. Open a newer export only when you want to bring in changes made in Planning Center (new families, room moves, new medical notes).
  • It is the only CSV, and it is read-only: the app never changes or saves it.
  • The first time ever, before a data file exists, open the export alone: it builds the roster, and the first Download data file asks for the club year and creates the file.

Starting from nothing: one Planning Center export is enough

You do not need a data file to begin, only this year’s Planning Center export.

  1. Import… the export alone (or drop it on the opening screen). It builds the whole roster: every person with their class, grade, birthdate, emergency contact, allergies and vest or shirt order. If Planning Center has changed its columns since the app was built, a window tells you what, and a bar under the header keeps the reminder (see When Planning Center changes its form).
  2. Download data file (or Save to Google Drive). With no data file yet it asks for the club year (it suggests the current one, such as 2026-27) and creates your data file. From now on that is the file you import each time; the export is only for merging changes.
  3. Calendar tab: use Make calendar to generate club nights, or Add date to enter a night by hand. Attendance, games and the quarter all come from the calendar.
  4. New club year, Options and Color teams. Options starts with an index (a Go to section list on a phone) that moves you to the section you pick; Validate and Debug are its last entry. Under New season a four-step New club year list says what is still to do (this year’s file, the calendar, Q1 colors, this year’s books), each with a Go. On Color teams, Fill blanks lets you choose this quarter or every open quarter before anything is written; More holds Re-draw, Import, Save colors CSV and Start new year. Edit on Roster opens the child’s Person page (Registration); All fields there is the full list of columns.
  5. Club-night helpers. On a club night (or the day after) the top of To do has a Tonight strip: classes entered, games entered, awards to announce, each with a Go; it is not part of the To do number. Options, Start on chooses what opens after a file opens (Roster, Tonight’s tab, or To do) and is kept in the data file. On Color team games, tap a number to set a team’s place or spirit and tap it again to clear it; Clear empties the row; when three different places are set the fourth team gets the one left (one Undo step), and ties are never filled in for you. Uniforms has Mark the N shown as ordered / received today, which touches only the rows shown that have no date yet. On To do the rows sit under one line per class (a class with something to do starts open; a class with only things to check starts closed); the name opens the Person page with what needs attention highlighted.
  6. To do tab: it lists what the export could not tell the app: children with no class or one that is not one of yours, color teams (Color team games, then Assign blanks), handbooks, missing grades and contacts.
  7. Options tab: check the standard settings you start with: the list of books and this year’s Cubbies and T&T book, how Sparks use their books, color order, game place points, Blue Jewel weeks and the store settings. The award lists themselves are fixed.
  8. Download once more, so the calendar and settings are in the file.

Importing and opening files

  • Merging another leader’s data file. File menu › Merge a data file… adds another copy’s changes to the one that is open (it never replaces it). Two leaders who each entered their own class or progress for the same night merge on their own. You first see a summary of everything the merge would do, grouped by Attendance, Game scores, Progress, Awards, Roster, Color teams, Uniforms and Flags, tagged Added, Changed or Review (you can filter it and download it). A blank never replaces a value: if the other copy cleared something that is still here, this copy keeps it and the row is marked Review. Only where both copies hold different values for the same thing do you choose: keep mine, take theirs, or type another. Nothing is saved until you press Apply, the merge is one entry in History, and Planning Center fields are never merged.
  • Import… (and the opening screen) accept one or several files at once, in any order. There is one button for everything you bring in; the rest of this manual says “import” or “open” for the same thing. The app works out what each one is from its contents, not its name: data file, Planning Center export, or a calendar or colors CSV.
  • An older season-only data file (from before the roster was stored inside) has no roster, colors or calendar of its own. The app says so when you open it by itself: open your newest data file instead.

Examples and templates for every file you can import

Five kinds of file can be brought in with Import…. The app tells them apart by their contents, so the file name does not matter (except the date at the start of a Planning Center export, and the date and time at the end of a data file). Each example below is a small real one: Copy puts it on the clipboard and Download this example saves it as a file you can change. They use made-up people. Every example here is checked by the test suite against the code that reads it, so what you see is what the app accepts.

Tips for CSV files. A CSV is plain text with one row per line and commas between the values; a value that contains a comma goes in double quotes ("Clubber (Cubbies, Sparks & T&T only)"). The first row is the column names, spelled as shown. Save as CSV (in Excel, CSV UTF-8; in Google Sheets, File → Download → Comma-separated values). The app does not read .xlsx files or Google Sheets directly. Dates in the calendar are yyyy-mm-dd; Planning Center’s own dates (birthdates) are m/d/yyyy.

Planning Center export (.csv) optional; only to merge changes from families

The registration list exported from Planning Center as a CSV, named something like 20261028 -- demo-club-2026-27.csv: the leading yyyymmdd becomes the “Planning Center data as of” date. The app only needs First Name and Last Name to recognize it; a real export has about 55 columns and they are all kept. The example has just the 15 the app reads: name, registration id, grade, birthdate, gender, selection, medical notes, emergency contact, the allergy question, the class and Uniform. Uniform is the one column saying a family ordered and paid for a uniform (anything but blank or No counts); it does not ask a size or which program, because the app works the kind out from the class and records the size itself. The older form had a column for each of Cubbies Vest, Sparks Vest and T&T shirt and a parent size question: those are still read if they are there, and none of them is needed. If one of those is missing from a future export, the app tells you what it affects (see When Planning Center changes its form). Money columns are kept but never shown. Planning Center has spelled the shirt column both T&T shirt and TnT shirt; the app treats them as one. The export is read-only: the app never changes it. After you import it you review the changes before anything is applied.

Test files

If a file you open has TEST as a word in its name (… TEST.csv, _test_, -Test-, in any capitals; a word like “latest” does not count), a red banner appears and the session is treated as test data: every download is named with TEST (before the date tag, for example awana-2026-27-TEST-20261104-190000.json) and the download buttons (Download data file, Download this slide, Download all) need two presses. The first press changes the button to “TEST data: press again to download” for ten seconds. Reload the page to clear it; opening a file that is already named TEST keeps the flag on. Try it out on the opening screen loads a complete invented club (the same files you would open yourself, kept on the server). Its dates are moved forward by whole weeks each time, so its newest club night is always the latest one on or before today and the demo never goes stale and Try an import in the red banner then imports a Planning Center export that adds 15 invented registrations, so every part of the app can be tried without real children.

Saving to Google Drive (optional)

If your copy of the app has been set up for it, the blue save button gets a small ▾ menu beside it (the same settings are on the Options tab). Without the setup the button is not there and nothing is ever sent to or loaded from Google; opening and saving files on this computer works as always. Setup and limits are in GOOGLE-DRIVE.md.

  • The save button. Without Drive set up it is just Download data file. With Drive set up, the ▾ beside it chooses where the file goes: This computer (download), Google Drive: a new dated file each time, or Google Drive: update one file in place; the menu also has Google Drive settings… (it takes you to the Options tab, where the folders, the sign-in and the rest are set: there is no pop-up) and Sign out. With a Drive choice the button reads Save to Google Drive (its tooltip says which style); after a save works it turns green and fades back to blue over about 18 seconds, and a small note beside it shows when it last saved. Importing from Drive switches Drive saving on. Choosing This computer goes back to downloading.
  • The import button follows the same default: Import… opens your computer’s file picker, and while saving to Drive is on it reads Import from Drive… and opens Google’s picker instead. With Drive set up, the ▾ beside it lets you pick From this computer… or From Google Drive… for one import.
  • Folders. One club files folder is used for both: the picker starts there and data files are saved there. Slide images, reports and exports can have their own folder (with none they go in the club folder): while saving to Drive is on, the slide images and their ZIP (Awards tab) and the CSV exports (store points, colors, calendar, rotation) go there. Print / Save as PDF opens your browser’s own print window, which the app cannot control: choose Save as PDF there and pick the same folder (or Google Drive) so reports, printables and slides end up together. The folders are kept in the data file, so everyone who opens it gets them; each person confirms a shared folder once, the first time Google asks. Older files that kept separate “open from” and “data files” folders use the data folder.
  • Save style (a setting of the data file, so it follows the file). Dated files (the default): every save is a new complete file with the date and time in its name; older ones stay as backups. One file, updated in place: the Drive file you opened is kept up to date and Drive keeps the earlier versions. Which to choose is in section 5 (Google Drive).
  • When several people save to the same file (in-place style). Before saving, the app checks whether someone else saved since you opened it. If they did, the same merge screen as File › Merge a data file opens: a summary of everything the two copies would combine into (Added, Changed, Review), then a choice for anything both of you changed to different values (keep what is on Drive, use your copy’s, or type another). Nothing is written to Drive until you press Save to Drive; if you cancel, nothing is written and a copy of your file is downloaded so nothing is lost. The merge is recorded as one entry in History. The automatic save has nobody to ask, so it keeps the older rule: what is already on Drive stays, and what clashed is listed afterwards. After a merge the screen reloads to show everyone’s changes (unless you changed something while it was saving, in which case the next save merges again).
  • What is ever overwritten. Only the Drive file you opened, or the file the app created for this season. A new season, a file opened from your computer, the Try-it-out club, or a test file in a session with a real file, always makes a new file. The file is renamed to the new date and time on each save, so the newest is still the one with the newest name. Nothing is ever deleted.
  • Keeping old versions. Drive keeps the earlier versions of an in-place file for 30 days (or until 100 newer ones). The app keeps one version forever every N days (default 30; set on Options, 0 = never), so Drive covers the last month and the kept versions cover everything older. Find them in Drive under Manage versions.
  • Try it once first. Before the club depends on in-place saving, try it on a copy of the data file in a throwaway folder.

3. Running a club night, step by step

  1. Open your newest data file (and, if you want updates, this week’s export: see section 6).
  2. Attendance tab. A child’s name is a link to their Person tab (from the keyboard, press P on a checkbox in the row), where you can change their class, color team or details; the Back to Attendance button at the top of the Person tab returns you to the same night and class, scrolled where you were (if you moved the child to another class, a message says where they went). Pick the Night (it starts on the latest club night up to today) and the Room. Tick Present for each child, plus Handbook, Participation and Extra where the paper sheet has them. Mark everyone present ticks the whole room; Clear this room unticks it.
  3. Color team games tab (Sparks and T&T; the teams are listed red, yellow, green, blue). Pick the night and group, then enter each team’s place (1 to 4) and spirit points (0 to 3). Standings update below.
  4. Awards tab. Three lists on two pages: To tell the group (Announce), then To hand out and the End-of-year awards (Hand out); one bar sets the group, class, sort and the night to announce on. Slide images… draws the awards earned and not yet announced as the 1920×1080 “Awards Earned” pictures (the name Awana’s slide template uses) (Cubbies, Sparks in three columns by handbook, T&T, Adult Memorization): download one, or all of them in a ZIP. Adults are typed in on that screen and saved in the data file.
  5. Person tab, Progress. Type the dates written on the paper Achievement Record, one child at a time. Cubbies are there too: Apple Acres (no award), the Trail (earns the Trail Emblem) and Units 1 to 6 (each earns a Green or Red Apple Emblem) of the AppleSeed and HoneyComb books, one box per unit or, if you prefer, one per Bear Hug (Options). Finishing a book earns its Book Award medallion.
  6. Download data file. If Planning Center changes are pending, a red warning appears first (see section 6).

Undo and Redo (next to Download data file, or Ctrl+Z / Ctrl+Y when you are not typing in a box) step back through this session’s edits one at a time: a tick, a note, a color, an award, a team move, even a whole import. Hover the button to see what it would undo. Undo is logged in History like any edit, so nothing is erased, and a new edit clears Redo. It starts once a data file is open, covers up to the last 100 edits, and is forgotten when you open another file or reload the page; report settings (quarter, club name) are not part of it. Every tick, score and award is also logged on the History tab as you go. You cannot lose work to a mis-click: you can compare any two versions and restore.

On a phone, a tablet and with a keyboard

Club night is usually run from a phone, so the app has a phone layout (a window narrower than 760 pixels) and works without a mouse.

  • Words used the same way everywhere. Class is a child’s class (never “room” in a label); Clubbers and Volunteers are the two kinds of people; Active, Inactive and Everyone is the one status choice on Roster and on Person; Binders is the Reports group of printed class binders, and Quarterly Printables is the bundle. Balance for: and Statistics for: mark a quarter that is only for that panel; the Color teams balance follows the grid’s quarter until you pick another, and says so when they differ. On Roster a class changes with Move… (the Class column is read-only); on a child’s Person page it is under Registration.
  • Roster filters. Filter the Roster from the dropdowns under the column headings (Class, Role, Active) or type in the Search box; a filter that is set is highlighted, and the Showing line under the bar says what is filtered and how many people are left. Clear removes them all. On a phone the same three are under the Filter line.
  • Learn on a computer, use the phone for convenience. The app is meant to be learned on a full browser, where every tab shows its own notes and (i) icons; the phone is for the quick jobs at the door (marking attendance, entering games, announcing awards, adding a flag). So a phone hides the (i) icons and keeps its screens short; Help for this tab in the ⋯ menu shows that tab’s notes when you need them, and this page has the rest.
  • On a phone the tab strip becomes one menu button showing the tab you are on and the To do count; only that button stays at the top while you scroll. The Tonight group (To do, Attendance, Color team games, Awards) is always open in that menu, so any of them is two taps from anywhere; Recent places is the menu's last group. In the slim top bar Download data file comes first. Tap the count beside it to review unsaved edits and unapplied drafts. Next are File, Undo and a ⋯ button holding Redo, Flag, Bug report and Search people, so nothing sits past the edge. On a phone the Person tab keeps Search, Person, Previous and Next in view and the other filters are behind one Filter: ... line that says what is set. The search (the magnifier, or /) lists names that start with what you typed before names that only contain it. A phone always works live: each tick is kept as you tap it, and the Hold changes box is ignored. Attendance repeats the N of M present count under the table, and the Progress record repeats Previous child / Next child at its foot. A wide table scrolls inside its own box, with a shadow at the edge that still has more.
  • On a tablet with a touch screen the checkboxes on Attendance and the date boxes, Today buttons and pickers on Progress are as big as on a phone (44 pixels). With a mouse they stay compact.
  • On a desktop the title bar and the tabs stay on top while the page scrolls, so the tabs and Download data file are always one click away. Dark mode follows the setting of your device; printed reports are always light.
  • With a keyboard. The first Tab stop is a Skip to content link (it appears at the top left while it has the keyboard): press Enter to jump past the top bar and tabs to the page. Tab moves through every control in reading order and each one shows a focus ring. In a pop-up window (the import review, a warning, a dialog) Tab stays inside it and Esc cancels it. On the tab strip the arrow keys, Home and End move between tabs. On Attendance, P on a checkbox opens that child; in a date box, Enter finishes the date. Ctrl+Z / Ctrl+Y undo and redo when you are not typing in a box, and / jumps to the search box in this manual. Anywhere else (not while typing in a box), / opens a search for a person by name, with tabs: People (opens the person's Progress), To do (only people with a To do item) and Awards. Up and Down choose, Enter opens, Esc closes.
  • With a screen reader. Every button, box and pick-list has a name; a box inside a table is named by its column heading and row (for example Size, a child’s name); each tab is a labeled region; status messages are announced. This was checked by script, not yet with a real screen reader, so tell the club leader about anything that reads badly.

4. Every tab, one by one

Recent places. From your second place on, a strip under the tabs lists the last 10 places you were at, such as Attendance · 10/28 · Sparks A or Person · a child’s name: the tab plus the night and class, or the child, you had open. Tap one to go straight back to it, scrolled where you were. The place you are on is highlighted; going back to a place already in the list does not add it twice, and moving to another child or night on the same tab replaces that place instead of adding one. On a phone the strip is one Recent places button that opens the list. The list is only kept while the page is open: it is never saved in the data file or the browser, and opening another file starts it over. Statistics

Three buttons across the top show one group at a time: Attendance (the whole club, by class, most nights present, Participation and Extra), Progress, awards and pace (the pace views, then the award and points leaders; they sit together because finished sections lead to awards and both are counted per night attended), and Color teams (team points). A night counts when it is a club night on the Calendar (not an Event, not No Club) and a child was marked present (volunteers do not count); the Awana store, Pace, the printed dates attended and the color-team turnout use the same rule, worked out from the data file’s own list of people (a volunteer-only night counts nowhere). Adults are marked present on the Attendance tab, under the room Volunteers.

Use it to set one class beside another; a class that is much faster or slower is a reason to go and watch, not proof of a different pass standard (the file does not record who signed a section or how the child passed it). Below it, children who already have 3 or more sections dated on or before their first night here (earlier work being entered, or a fast start).

Awana store points

  • What each child can spend at the Awana store at the end of the year. Each earning (nights present, handbook, participation, extra, game place and spirit points, awards, and sections signed off on Progress, on the Person tab) is multiplied by a weight; the total is the child’s raw score, and the method turns it into store points between your minimum (15) and maximum (200).
  • Direct: the weighted total is the points, held between the minimum and maximum, so the weights are store points per earning. Proportional: the best child gets the maximum and everyone else in proportion (at least the minimum). Range: the lowest child gets the minimum, the highest the maximum.
  • If you type a minimum above the maximum, a warning appears and the maximum is treated as the minimum until you fix one of them; nothing is changed behind your back.
  • Programs in the store: tick the programs that take part. Puggles and Cubbies do not at our club, so only Sparks and T&T are ticked; tick Cubbies (or Puggles) to include them. Children in an unticked program are left out of every total, table and the CSV.
  • Projected to the end of the year (Direct method only) assumes each child keeps the pace so far for the club nights still to come, so you can tune the weights before the year is over. A past night nobody entered is not counted as still to come. So far shows only what has been earned. With Proportional and Range the projection would always equal so far (the pace cancels out), so it is not shown. Awards that everyone gets (the ones excluded from the slides) are not counted.
  • Participation and Extra by class repeats the Statistics table and adds, for each class, how many nights the average child has the mark and how much of the class’s store points it makes up at the current weight. A mark given to nearly every child mostly repeats attendance; where classes differ a lot, the same mark is worth different amounts depending on the class. Set its weight to 0 above to see the share fall to nothing.
  • The tables show where the points come from (each earning’s share of everything given out, so you can see which one dominates), how the children spread across the range, how each program does, and every child. Scale weights so the top child reaches the maximum (Direct method only) multiplies all weights to fit; Download as CSV saves the list. The settings are saved in the data file and carry over to next season.

Color team games

How teams are chosen and balanced

Always first: (1) a child never repeats a color in the year (a move counts as played); (2) a new child is placed with a friend when that can be done; (3) team sizes stay within one child of each other. Nothing below can break these.

Then the goals, in the order set on the Options tab: keep earlier teammates apart; even expected attendance across the teams; spread each grade. The first goal in the list weighs most, and any of them can be switched off.

Expected attendance is how many children each team can expect on a night: the sum of its children’s turnout, where a child’s turnout is the share of club nights they came to, counted from the first night they came. A child with fewer than 3 counted nights this season uses their earlier years (all years pooled); with no history, the group average. As this season fills up the two blend: this season counts for none of it at 3 nights and all of it at 20 nights (the number is set on Options). So a team of regulars and a team of children who rarely come are told apart, and the plan puts a mix on each.

Balance now (above the grid) shows each color’s children, expected a night and gap to the average, and says in plain words when one team has the regulars.

Set by hand, suggested and locked: a color you set by hand is drawn solid and is never moved. A suggested color has a dashed outline: it is a projection that Fill and Recalculate can change. A locked quarter, and a dated move, are never changed. Manual picks are always allowed: the move box warns when a pick repeats a color or makes the teams uneven, and still lets you do it.

Games are scored per team, not per child: enter each color’s place (1 to 4) and spirit points (0 to 3). Every child on that team that night shares the points. The points for each place (3, 2, 1, 0 to start) are set on the Options tab. The colors are listed in the order set there too.

The Progress sheet: dates, books and pace

Dates on the record

One child at a time, like the paper Achievement Record. Type the date from the sheet, or tap Today (it reads Now on a phone). Which book opens first, and received dates

The tab shown first is the book the child is in. Sparks work through HG, WR, SS in order (Options → Books), so it is worked out: the book received most recently that is not finished; else the handbook on file; else the book after the last one finished (finishing Wingrunner puts a child in SkyStormer, even if Hangglider was never recorded); else the book they signed off most recently. Type the date received in the row under each book’s tab; Finished before (at the foot) counts books done at another club. Pick another tab freely; it stays picked until you move to another child.

Cubbies and T&T all use one book together, so the handbook (Person tab) or this year’s book decides.

The pace strip

Pace is how many core sections a child gets signed per night attended (not per calendar week): Flight 3:16, Rank, the Sparks jewel sections 1 to 4, and the T&T Start Zones and emblem sections. Sparks reviews and T&T Silver / Gold are counted on their own line and never move it, because they can happen long after the section.

A section lands on the first night the child was present on or after its sign-off date, so a month signed off in one visit is one tall bar, not a gap. About 1 a night is the goal; the strip shows overall, the last 4 nights, and an arrow when recent pace has dropped or risen against the child’s own. A child can be listed needs encouragement, steadily slow or capable, slowed; the Pace watch list report prints them by class. The numbers are first guesses to tune on real sign-off dates, and nothing about who signed or how many tries is recorded: room against room is a reason to go and watch, not proof of a different standard.

Awana store points

Which method to use

  • Direct — the weighted total is the points, held between the minimum and maximum, so each weight is “store points per earning”. Choose it when you want to say what an earning is worth. It is the only method with a projected to year end view.
  • Proportional — the best child gets the maximum, everyone else in proportion (at least the minimum). Choose it when you want the top child to always hit the cap whatever the weights.
  • Range — the lowest child gets the minimum, the highest the maximum. Choose it to spread children evenly across the whole range.

With Proportional and Range the pace cancels out, so the projection would equal so far and is not shown.

Weights

Each earning (nights present, handbook, participation, extra, game place and spirit points, awards, sections signed off) is multiplied by its weight. Look at Where the points come from: a large share is a lever, so a small change to that weight moves everyone. Scale weights multiplies them all so the top child just reaches the maximum (Direct only). Participation and Extra are the two to check: where a class gives them to nearly every child they only repeat attendance.

This year

Sparks: in order or all together

In order, at each child’s own pace (Awana’s standard, and the default). Flight 3:16, then HangGlider, WingRunner, SkyStormer; a child finishes a book before the next, whatever their grade. A child who starts late catches up by moving on as soon as a book is done; finishing all three by the end of 2nd grade earns the Sparky award. All together. The whole Sparks club uses one book this year (HG one year, WR the next, SS the third). It simplifies leader preparation but is a local choice, not Awana’s standard track. Use it when you want one lesson plan for the whole room and a late starter can catch up another way.

Cubbies: one box per unit or per Bear Hug

Each Cubbies handbook (AppleSeed, HoneyComb) is 26 Bear Hugs: the Trail (Bear Hugs 1 and 2, earning the Trail Emblem) and six units of four (Units 1, 3 and 5 earn a Green Apple Emblem; 2, 4 and 6 a Red one). Switching to one box per unit is refused while a unit is only partly done, so no date is lost.

Color order

Only the order the four colors are listed in: on the Games tab, team pickers, the Color teams list, standings and the printed reports. It changes no data. Match it to the order on your game sheet (red, yellow, green, blue to start).

Balancing goals

When two goals collide, the higher one wins. Never repeating a color and even team sizes always come first (and a new child joining a friend, when children are placed). A locked quarter, a color you set by hand and a dated move are never changed. Below those you choose the order, and switch on or off: keep earlier teammates apart, even expected turnout (from each child’s past attendance; a child with fewer than three counted nights counts at the group average) and spread each grade across the teams. Game place points

What each finishing place is worth in the standings (3, 2, 1, 0 to start). Whole numbers, 0 or more. Changing them re-scores every past night, because points are worked out from the places entered.

Four rising numbers (6, 12, 19, 27 to start): a Sparks child earns Blue Jewel 1 on the night of their 6th time present, and so on. The paper record says 27; the old Sheet used 31.

6. Planning Center: updates, reviews and the changes report

Planning Center is the source of truth and is never edited here. The app only ever reads its export. If something must change in Planning Center, the app keeps a list for you to make those changes there.

Merging an update

  1. Export from Planning Center and import the CSV (together with your data file, or afterwards with Import…).
  2. People the app already knows are refreshed silently. If anything important changed — a new, missing, renamed or reactivated person, or a changed name, room, grade, medical, allergy, emergency contact, selection or birthdate — a review window opens first, listing each change. Possible renames let you confirm that two rows are the same person; new people and missing people have checkboxes. Nothing is applied until you press Apply import; Cancel discards it.
  3. Missing people are marked inactive, not deleted; people you added by hand are never offered for that. Someone you marked inactive yourself stays inactive even though Planning Center still lists them (a cancelled or duplicate registration stays in the export); the review has an unticked Make active again box if you want them back. Only people the import itself marked inactive come back by themselves. The rename list shows room, grade and birthdate under each name, and a pair whose birthdates differ is not pre-ticked. If you pick several data files at once, the newest one is opened and the others are named in a message. A phone or email change is applied quietly and marks the file as changed.
  4. An export identical to what the file already holds changes nothing.
  5. When the import finishes the To do tab opens with the file check and what the new people still need (see the To do section).

Changing something that comes from Planning Center

  • In a row’s Edit dialog, change the field and save. It is recorded as a pending Planning Center change: reports use the new value right away, and the change is listed on the Changes needed in Planning Center report.
  • Make the change in Planning Center. When a later export matches, the pending change clears itself. If Planning Center is changed to something else instead, the import review says your pending change is out of date and drops it (Planning Center wins). Cancel change in the Edit dialog drops one.

The red warning

When you press Download data file while changes are still pending, a large red warning lists them with a link to the changes report. Save anyway downloads the file (the pending changes stay recorded in it); Cancel goes back.

When Planning Center changes its form (new, renamed or missing columns)

Planning Center’s registration form can change from year to year: a new uniform item, a reworded question, a dropped field. The app reads the export by column name, so every import (including starting from one export alone) checks the columns against what the app reads, and nothing is guessed silently:

  • Renamed. If a column the app uses is not there but exactly one other column clearly means the same thing (for example Class Assignment for Assignment Area: Classes, or a reworded allergy question), it is used in its place and you are told which.
  • Missing or ambiguous. If the app cannot find or choose a column, a window opens (and an amber bar stays under the header; Details reopens it, Hide hides it until the next import) saying which column and exactly what will not work as a result: no classes means every child shows as Unassigned; no grade or birthdate means they all appear on the To do list; no vest or shirt column means that order is not tracked on the Uniforms tab; and so on. The people are imported either way, and the details can be filled in by hand on the Person tab.
  • New. A new column that looks like a uniform item or a size question (a hoodie, a belt, a polo) is flagged because it will not be tracked on the Uniforms tab. Any other new column is listed as a note. All of them are kept with each child (Roster, All fields) and saved in the data file, just not used.
  • Only a missing First Name or Last Name stops the import, because the export cannot be read without them.
  • The same list is on the Debug tab and in the Validate tab’s check of an export, so a new export can be checked before it is imported.

What the app reads: Registration ID, First Name, Last Name, Grade, Birthdate, Selection, Emergency Contact, Medical Notes, the allergy question, Gender, Assignment Area: Classes, Uniform (or the older Cubbies Vest, Sparks Vest and T&T shirt columns and the parent’s shirt-size question, which are optional). Adding a new tracked item (a new uniform, a new question the app should use) is a small change to the app; ask for it and send an example export.

9. History, naming versions and restoring

  • Every edit is logged inside the data file: what changed, the old and new value, and when. Edits to the same night within five minutes share one entry. Version 0 is the file as it was opened. The log makes the file grow slowly; New season… starts a fresh one.
  • Comparing. Pick a day, then a time, for each side. The tab highlights the differences: green added, red removed, amber changed, with names and plain-words descriptions. Tick always the latest to compare any earlier version with the current one. The ‹ and › buttons step through versions, and a table shows how each night’s attendance, awards and games changed.
  • Naming. Name… puts a label on a version (for example “before Q2 colors”). A named version is never added to by later edits.
  • Restoring. Restore to version N… asks you to confirm, first downloads a backup of the current file (awana-…-before-restore-….json), asks again, then deletes every later version and loads version N. It restores everything in the file (colors, uniforms, calendar, rotation and the stored Planning Center record) and leaves the file unsaved until you download it. The next import refreshes the Planning Center record.

10. Troubleshooting

  • A tab says “Load a roster first” or “Open your data file”. No roster is open yet. Open your newest data file. If you open an older season-only file you will get a message saying it has no roster, colors or calendar.
  • Colors or the calendar are missing. You probably opened an old file. Open the newest awana-…-yyyymmdd-hhmmss.json, then run Validate on it.
  • The review window appeared and I do not recognise a change. Press Cancel: nothing is changed. Check the person in Planning Center, then import again.
  • “Not a file this app knows how to open.” Use Validate on it to see what it looks like. The app opens data files, Planning Center exports and calendar, rotation and colors CSVs.
  • The page asks if I want to leave. You have unsaved changes. Press Stay, then Download data file.
  • “N changes are needed in Planning Center” will not go away. That count is edits you made here to a Planning Center field. Planning Center does not have them yet, and this app never edits Planning Center. Make the same change in Planning Center and import the next export: the note clears itself when the export matches. To drop an edit instead, open the person and press Cancel change beside the field. See the list opens the report of every one.
  • An award shows “(no date)” or a Given date will not appear. It was marked given with the no date tick. Type the real date into the Given box (on Progress) if you learn it; un-tick no date to take the give back.
  • A phone number is flagged but looks right. A phone box may hold several numbers with names and extensions (Mom: 513-555-0147; Dad 937-555-0100 ext. 12). Each number needs 7 to 15 digits; separate numbers with ; & / a comma or the word and. A number written with slashes in three groups of 3, 3 and 4 digits (937/555/0142) is read as one number. A box with no digits at all is flagged.
  • I downloaded the file but cannot find it. Look in your browser’s Downloads folder for awana-…. Move it somewhere you will find it, and keep the older ones until you are sure the newest opens.
  • I made a mistake. Use the History tab to see what changed and restore if needed. If you have already closed the page, open the previous data file.
  • A printed sheet looks wrong. Use your browser’s print preview: set margins to default, scale 100%, and turn on Background graphics for colors. Landscape or portrait is set by each report.
  • A “Club night” shows a yellow warning in the Day column. It is not on your club’s day. Fix the date, change its Type to Event, or change Club meets on.
