# Changelog

What changed in each app version (the `app-version` in `dev/app/index.html`, shown in the title bar and on the Debug tab). Dates are 2026. Versions before 1.50 are taken from the commit messages, which skip some numbers; the work on 1.46 to 1.49 was committed only as part of 1.47 and 1.50.1, so those entries are reconstructed. Versioning for now: stay in the **1.51.x** series (it was 1.50.x before 1.51.00) and bump only the third number; the minor number waits until leaders are told about releases. **1.50.2 was never shipped** (reserved by the Color teams plan, which will renumber).

The public repo was reset to ONE commit for it, because the 1.51.12q commit had real children's names and a phone number in BACKLOG.md; the old commit is no longer on any branch but GitHub still serves it by its hash until it is purged (ask GitHub Support). ## 1.51.16 (unreleased; includes 1.51.15h below)
One release for the whole open backlog except the club calendar maker (N3). **Every leader should press Update now before anyone marks a report Dropped or types lessons by week**: an older copy keeps the new fields but does not show them.
- **Attendance sheet (BACKLOG N8, N11).** The rotated "Attendance" word is centered in its column on every class (a screen-only rule had pushed the second one to the left and made the Puggles and Cubbies tables narrow on paper); Puggles have one box a night, so they have no rotated row and the date alone heads the column. Every page holds 20 rows, not 25, and the top of the page is left clear (0.85in from the paper edge) for a three-hole punch; a class of more than 20 goes on to "page 2 of 2". The sheet now carries "Printed MM/DD/YY", so the browser's own date and time line can be turned off.
- **Coaches notes sheet fits one page (N16).** A long theme could grow a night's block and push the quarter onto a second page. The theme now sits in a clipped box the height of its rows (smaller type for longer themes), the row budget has slack, and the phone layout no longer applies on A4 paper.
- **Child record sheet (N12).** On the printed Sparks sheet the review rows come after the last jewel (labelled "RJ1 review" and so on), then the Review Emblem row, Blue Jewels and the Book award. The two left bands are worked out from the rows. T&T and Cubbies sheets are unchanged.
- **Emergency, Medical and Photos (N15)** uses the same fixed column widths on every class and on the everyone-by-name page; a long name wraps inside its column. **Volunteer Contact List (N13)** is ordered by class, then last name, with volunteers who have no class last.
- **Print class binders (N14).** The report list entry that was called "Your binders" is now "Last made in Print class binders: ..." (it is the set you made last, not a different binder), and the help says so.
- **Person tab (N6).** A volunteer or a Puggle (no progress sheet) opens on Registration instead of an empty Progress page; a child opens on Progress; a sub-tab you picked yourself is kept, and clicking Progress for a volunteer still shows why it is empty.
- **Splash screen (N7).** The start screen says "Checking for updates...", then "Checked for updates at HH:MM", or "Could not check for updates (offline)", with no click. A click during the launch check waits for it (one request). The service worker marks an offline answer, so an installed app no longer reports "latest version" from its own cached copy.
- **Bug reports are a conversation (N17, N18).** Each report holds any number of replies, each with the date and whether a leader or the developer wrote it (Reply adds one, Remove takes one back with Undo). Replies are an object keyed by reply id, so replies added on two copies both survive a merge. The statuses are Open, Fixed and Dropped (a pick on each row, saved at once); a reply never changes the status. "Answered" is retired: an older file's answered reports open as Open (logged as one File upgrade). The older single reply is still shown as the first reply. A new season carries only the open reports. The file check warns (no longer errors) on a status it does not know.
- **Lessons by week (N2).** The calendar has one lesson column per group (Puggles Lesson, Cubbies Lesson, Sparks Lesson, T&T Lesson); the older Puggles # and Puggles Title columns are joined into Puggles Lesson when a file is opened (not logged in History) and an older calendar CSV still imports. The Calendar tab has a new Lessons by week view: a row for each club night, a box for each group that is switched on, NO CLUB rows, and switches per group (Sparks work through their books in turn, so they usually have no lesson by week). The switches are `config.lessons` in the data file. The Lessons by week report prints Date, Theme and the groups that are on. Series numbering, cancellations and the calendar maker stay with N3.
- **A flag is tied to the view it was made in (N20).** Flagging one child's *Date received* box used to light that box on every child, because a Flag-anything flag stored only labels. It now also stores the child, the part of the Person tab that was shown (Progress, Attendance, Awards or Registration), the book tab, and for Attendance the night and class, and is looked for only there; a flag that names a child is only ever that child's element, even in a table that shows many children (Attendance, Uniforms, the Color teams grid, which now names its child in `data-kid`). **Go** opens the child, the part of the tab, the book and the night first. Such a flag also shows in that child's sheet note list. Flags made before this have no view stored and match as they did (your real file has one such flag, on Uniforms). Older copies keep the new fields but still show the flag everywhere. Data format version unchanged; one new optional flag field, `sub`; the file check only warns.
- **Hide a note or flag on To do (N19).** Each row of the Notes and flags card has **Hide** (also on the child's sheet and in the yellow-flag popup): the note leaves the card's list and its number (the To do tab's own number never counted notes) but stays on the child's sheet, the yellow flag and in History. **Show hidden (n)** lists them greyed with **Unhide**; that choice is remembered in the data file (`config.showHiddenNotes`). The hidden state is `hidden: 1` on the note itself, so two leaders' hides merge. Older copies keep the field and list the note as before.
- **Google Drive save failures say what happened, with Try again (N9 point 9).** A save you press that fails now shows one plain sentence (sign-in, a folder Google will not take, Google busy, no connection, or another problem) with **Try again** and **Close**. The copy still downloads, once. Try again saves the way the first attempt did, so it cannot overwrite a newer Drive revision. Files: `drive.js` 1.3.3, `app-drive.js` 1.20.0, `app.js` 1.75.2.
- **Saving indicator (N36).** A small floppy icon beside Save to Google Drive fades in while a save runs and out when it ends.
- **Club night pack (N9 point 13).** A standard bundle of the announce list and the hand-out strips; a club with its own bundles gets an "Add the standard bundles you do not have" button (its own bundles are not changed).
- **Offline chip (N9 point 8).** While this browser is offline the top bar says so, in plain words.
- **Source on the Debug tab (N9 point 7).** The published page names the commit it was built from ("Built from"); each Pages run records commit, version, build and the test result on its summary.
- **Stricter Pages gate (N9 point 1).** The Pages test job runs the deploy check strictly, and a test checks that deploy/ holds only app files, invented TEST data and no secrets.
- **Process (N9).** The Pages workflow runs the node tests first (a non-blocking `test` job until it has passed once on GitHub); every pending phone and paper check is in one list in `docs/reference/playtest-checklist.md`; new browser tests share `test/lib/app-page.js`, and `run-tests.sh --node-only` skips any test that uses it.

## 1.51.15g (released Nov 18)
- **The app checks for a new version once as it opens (BACKLOG N5).** The first version check used to wait 15 seconds after the scripts loaded, so an installed PWA that served its cached copy could run the old release for a while. It now runs 1.5 seconds after the page's `load` event, after the session restore, as the last step of start-up: it asks the site for `index.html` and starts the service worker's update check (the same `check()` the timer uses), so a newer release is found within seconds and the usual Update now / Later bar shows. It only shows the bar (never applies an update), does not hold up loading, is silent when the site cannot be reached, and the timer restarts after it so a second check does not follow a moment later. `app-update.js` 1.6.0. Tests: `update-launch-browser.test.js` (5); `update-autosave-browser` still passes (12).
