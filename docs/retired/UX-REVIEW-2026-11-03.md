## Accessibility audit of the "unchecked" areas (v1.50.1), with evidence
Method: Playwright against the demo club, all tabs, light and dark, plus a phone-width keyboard pass. Script results, not eyeballing, except where noted.

**Already good (leave alone):** every focusable control on every tab shows a focus ring (checked by walking Tab and reading computed outline / box-shadow; the only `outline:none` rules are on menu buttons and info icons that draw their own highlight); no positive `tabindex` anywhere; Tab order is natural on Progress, Calendar and Help. (An apparent "short tab loop" on those three was my script's duplicate detection, not a trap.) "Clear this room" asks first ("Clear every mark for Sparks A on 10/28?") and does nothing if cancelled. Modals make the page inert and Esc cancels, with focus returning (existing tests). Phone tab menu works by keyboard: Enter/Space on the menu and on group headings, Esc closes it and returns focus to the menu button. Contrast: no text failing WCAG AA (4.5, or 3 for large) on 13 tabs in light and dark by computed colors (589 text nodes sampled on To do; the lowest ratio there is 5.6). Caveat: computed against flattened background colors; images and gradients are not assessed.

**Fixed:**
| Finding | Fix and reason |
|---|---|
| In a dialog (import review, warnings), Tab off the last control dropped focus to the browser toolbar; Shift+Tab off the first did the same. With the page inert it is not a trap, but a dialog should wrap. | `app.js` 1.28.0: one keydown handler beside the existing Esc one wraps Tab / Shift+Tab inside the open dialog. Scoped to the three existing dialog ids, so no other focus behavior changes. |
| About 1,300 table-cell inputs had no accessible name (Roster flags, Uniforms, Calendar, Rotation). A screen reader announces the column heading when moving by cell but not when you Tab in, so you hear "checkbox" with no context. | `app.js` `nameCells`: after any change under `main`, controls without a label get `aria-label` = column heading + row (for example "Size, Bodhi Buckley"). Only adds an attribute; never overrides a label, title or `<label>`. Rotation has no `<thead>` (its headings are editable inputs), so it reads the first row, and a first draft that named cells "Delete" (from a button cell) was caught by checking real output and fixed before shipping. |
| Attendance checkboxes were about 20px on a touch tablet (820px uses the desktop layout). | `style.css`: under `(pointer: coarse) and (min-width: 761px)` the checkbox gets a 44px tap area. Mouse users keep the compact rows. |

**Tests added:** `test/a11y-browser.test.js` (cell names on four tabs, rotation not named "Delete", Tab and Shift+Tab wrap inside the real import review). Existing focus tests (`leftovers-browser`, 60/60) and `versions`, `season` re-run and pass after the change.

**Still not verified:** a real screen reader (NVDA/VoiceOver) was never run, so the names are checked for presence and wording, not for how they are spoken; zoom/text-size at 200%; reduced-motion; Windows high-contrast mode; the Reports print layout; tablet and dark visuals beyond the two screenshots I looked at (tablet Attendance leaves a wide empty area right of the table: cosmetic, left alone).

## Second accessibility pass (v1.50.1): screen-reader semantics, tablet / desktop / dark visuals
Asked to finish the items still marked unchecked. Results:

**Screen-reader semantics (scripted, all 18 tabs):** `lang="en"`, a page title, a viewport meta, one `main`, a `tablist` with 18/18 tab roles and the selected one marked, live regions for status, each tab section already labeled by its tab button (`aria-labelledby`, app.js), no duplicate ids, no images without alt, no icon-only buttons without a name, and the info icons all have names. Heading order has no skipped levels.
Gaps found and fixed:
| Gap | Fix and reason |
|---|---|
| 10 standalone controls had no name: Roster search / room / role filters, Person search, award date and award pick, Uniforms filter, Store program and sort, the Reports report picker. (A placeholder or nearby text is not a label.) | Added `aria-label` in `index.html`, `app-person.js`, `app-store.js`. Visible text is unchanged. Re-run: zero unnamed standalone controls on any tab. |
| 70 To do items and 1 award row are one-row tables with no heading cells (a list item laid out in columns), so a screen reader announces "table, 1 row, 5 columns" for each. | `app.js` `nameCells`: a table with one row and no `th` gets `role="presentation"`. Cells and buttons inside stay reachable. The Rotation table is a real editable grid, so it is left alone. |
Rejected: adding a visible heading to every tab (it would change every layout for a benefit the existing region labels already give) and marking all tables presentational (would hide real data tables).

**Tablet (820px), desktop (1280px), dark mode:** reviewed To do, Attendance, Progress, Statistics, Reports, Options, Roster and Awards at tablet and desktop, light and dark (screenshots in the session scratchpad, not kept in the project). Dark mode reads well everywhere I looked: contrast holds, the info icons, badges and pace strip stay legible, and Reports stays on white paper by design. 
Fixed: on a touch tablet the Progress date boxes and "Today" buttons were about 24px tall (the 44px rule stopped at 760px). `style.css` now applies 44px under `(pointer: coarse) and (min-width: 761px)`, scoped to the Progress tab. Measured at 820px: Today 44, date box 44, pickers 44.
Observations, not changed: (1) on desktop the sticky block (title row, tabs wrapping to two rows, Recent places) is about a quarter of a 1280x800 window; sticking it is deliberate (the Apply bar and table headings sit under `--stickyh`), so shrinking it is a design decision for you, not a bug; (2) on tablet the Attendance table uses about two thirds of the width and leaves empty space; cosmetic.

**Still not verified:** a real screen reader (NVDA, VoiceOver) was never run, so everything above is presence and wording, not how it is spoken; browser zoom at 200%; Windows high-contrast mode; reduced-motion; print layout of Reports (not looked at); Firefox and Safari (everything ran in Chromium 1.63 only).
