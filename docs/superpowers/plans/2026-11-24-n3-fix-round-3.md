## A. First calendar blocked by non-sign-off records (blocking)

**Problem:** `calendar-safety.js` (around line 141, called from `propose`) still blocks Apply with "season classification would change" when an award receipt, book receipt, handbook or jewel falls before the first night. Owner decision 2 says any date can be entered. Round 2 only changed sign-offs. With no carried-through cutoff, the optional cutoff helper does not appear, so there is no way forward.

**Required:** apply the same rule to every record kind: a notice listing the affected records (kind, child, date, new first night), not a block. Keep the cutoff helper optional. Apply stays enabled unless a genuine data problem exists.

**Tests:** a blank season with an award receipt before the first night applies with a notice. Add the same for a book receipt. A genuine data problem (duplicate meeting, invalid date) still blocks.

## B. Save can lose a pending repair if the reply is lost (blocking)

**Problem:** `drive.js` (`pendingWrites`, around line 131 and line 181). `pendingWrites` is set only after `update()` returns. If the upload reaches Drive but the reply is lost, the repair is never recorded and the next save treats the unknown write as the head. An edit it displaced can be lost without a message.

**Required:**
- Record a pending entry with the base revision **before** the upload is sent.
- On recovery, look for the write that follows the base revision. If found, treat it as ours and proceed. If not found, treat the upload as not stored and retry within the existing limit.
- If the pending state cannot be resolved, fail closed with a clear message that names the file and says a save needs checking.
- Also: a third save during recovery must not leave the file unusable for the rest of the session. Clear the pending state on reload or on a successful recovery, and say so in the status line (finding 6).
- If the revision list lags behind the write, retry with a clear message, not "cannot match revision IDs" (finding 7).

**Tests:** a fake transport that stores the upload but drops the reply. Assert that the next save recovers, merges any displaced revision, and does not lose it. A test for the lagging revision list. A test that a third save during recovery does not wedge the file.
